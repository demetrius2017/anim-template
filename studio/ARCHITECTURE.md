# Movie Studio — архитектура v1

18 октября 2026. Решение председателя консилиума для обсуждения владельцем; возможности ниже предстоит реализовать. Основание: позиции [A — шоураннер](consilium/A_showrunner.md), [B — архитектор](consilium/B_architect.md), [C — продюсер](consilium/C_producer.md), исследования [R1](research/r1_prior_art.md), [R2](research/r2_genai_api.md), [R3](research/r3_story_library.md), [R4](research/r4_craft_style.md), [R5](research/r5_engine_audit.md).

**Моя позиция:** студия связывает доказательство, постановку и принятый кадр. Качество подтверждает понятный и выразительный выпуск. Сохраняем SVG/JS; над ним строим Python-конвейер с проверяемыми документами и ответственным шоураннером.

## Конвейер и ответственность

| Этап / ответственный | Вклад и результат | Условие передачи |
|---|---|---|
| Исследователь → научный редактор | Досье первоисточников, реестр утверждений, карта механизма, альтернативы и неизвестное | Каждая центральная причинная связь обоснована; расчёты воспроизведены или обозначены учебными |
| Шоураннер | Бриф: аудитория, вопрос либо конфликт, обещание, границы, жанр, бюджет | Замысел соответствует поручению владельца |
| Сценарист → комната сценаристов | Биты, реплики, изменение знания/состояния, паузы | Закрыты блокеры фактов, причинности, хука и финала |
| Режиссёр и художник | Действие, фокус, масштаб, камера, непрерывность объектов; опорные кадры | Постановку можно проверить дешёвым аниматиком |
| Монтажёр | Черновой аниматик с речью; длительности, паузы, переходы, сокращения | Зритель понимает действие и успевает прочитать результат |
| Звукорежиссёр → монтажёр | Голос, тишина, среда, предметные эффекты, музыка; затем чистовой монтаж | Звуковые акценты поддерживают смысл, изменения времени согласованы |
| Codex: исполнение | SVG-сцены, необходимые внешние вставки, сведение, рендер | Пройдены технические проверки и просмотр |
| Независимая приёмка → владелец | Заключения по точному MP4, фактам, пониманию, стилю, слуху, правам | Нет блокеров; обязательные проверки выполнены |

Шоураннер отвечает за целое, режиссёр — за постановку. Научный редактор проверяет также подписи и изображённые связи после монтажа. В драме исследование проверяет контекст и правила мира; художественный выбор не требует научного доказательства.

Комната: три независимых прохода одной версии — фактчекер с проверкой логики; драматург с хуком/финалом; редактор ясности в роли новичка. Они сначала не видят чужих оценок. Жанрового критика добавляем по конкретной задаче. Замечание: `revision, beat_id, defect, severity, evidence, close_when`. Два круга: диагностика и проверка исправлений. Третий — только для названного остаточного дефекта. После двух бесплодных исправлений пересматриваем конструкцию. Хакатон при тупике: две альтернативы, до 90 минут, одинаковое досье, выбор одного аниматика; фактическую ошибку голосованием не снимаем.

## Контракты

Оболочка JSON: `schema_version, artifact_id, episode_id, revision, inputs[{id,sha256}], producer{role,model,prompt_sha256}, payload`. Редакции неизменяемы. Markdown объясняет решения, JSON передаёт данные.

| Документ | Обязательные поля внутри `payload` | Короткий пример значения |
|---|---|---|
| `brief` | `audience, question_or_conflict, outcome, exclusions, genre, style, duration_range, budget, acceptance` | `outcome: "Зритель замечает подсказку из будущего"` |
| `claims` | `id, text, type, confidence, evidence{path,url,fragment,sha256,date}, conditions, limits, allowed_wording, visual_constraints, status` | `type: "observation"`; `visual_constraints: "Не рисовать неизбежное падение доходности"` |
| `mechanism` | `nodes`, `edges{from,to,claim_ids,conditions,alternatives}` | `from: "сегодняшний список", to: "прошлый тест"` |
| `script` | `beats{id,before,action,after,claim_ids,phrase_ids,pause_intent}`, `phrases{id,spoken_text,display_text,tokens,voice}` | `pause_intent: "Дать заметить неверную дату"` |
| `shots` | `id, beat_id, purpose, focus, before, action, after, source, anchors, camera, continuity, transition, caption_policy` | `source: {kind:"scene",name:"dated_list"}` |
| `style` | `id,version,colors,fonts,safe_zones,layouts,motion,camera,transitions,sound_motifs,examples` | `motion: {enter:"easeOut",hold_ms:600}` |
| `sound` | `buses, events{id,anchor,asset_id,bus,gain_db,pan,required}, silence, ducking, targets` | `bus:"foley", required:true` |
| `timeline` | `fps, sample_rate, duration_frames, clips, markers, token_map` | `fps:30, sample_rate:48000` |
| `asset` | `id,sha256,source,model,parameters,rights,attribution,review_status` | `review_status:"accepted"` после проверки файла |
| `qa` | `manifest_sha256, output_hashes, checks, reviewer, evidence, issues` | `checks: {technical:"pass",listening:"unknown"}` |

Примеры сокращены; `dated_list` — будущая сцена. Тип основания и уверенность различаем; `verified` требует прочитанного фрагмента.

Авторское время задаём словами и событиями: `{token_id:"p3.then",offset_ms:-50}` или `{after_event:"list_replaced",hold_ms:600}`. Компилятор разрешает зависимости в целые кадры и аудиоотсчёты; интервалы `[start,end)`, округление единое. Итоговый `timeline` управляет речью, титрами, действиями и звуком. Пауза сдвигает все зависимые события. Исходные тайминги TTS сохраняются отдельно; словесное число связано с отображаемой цифрой через `token_map`. J/L-стыки имеют разные границы изображения и звука.

Валидатор отклоняет неизвестные поля/сцены, потерянные ссылки/ресурсы, циклы, неоднозначное время, пустоты и недопустимые перекрытия. Истинность и выразительность проверяют отдельно.

## Репозиторий и оркестраторы

```text
studio.py                 CLI: validate, plan, run, status, resume, qa
studio/
  roles/ genres/ styles/  инструкции, шаблоны, готовые решения
  schemas/ registry/     контракты, возможности и параметры сцен
  pipeline/ compiler/    состояния, решения, хэши, время, экспорт
  adapters/ tests/       TTS, локальное медиа, WaveSpeed, проверки
  research/ consilium/   основания решений
eps/<episode>/
  source/ studio/        доказательства, авторские документы
  assets/               локальные файлы и паспорта
  runs/<id>/            manifest, approvals, events, logs, status
  build/ audio/ qa/ out/ производные результаты
```

Пилот — `eps/spy_studio`; `spy_flow` сохраняем. `story.py/mix.py` продолжают работать. Компилятор экспортирует совместимые данные; неподдерживаемые возможности отклоняет. В Git — код, контракты, решения, паспорта; медиа — в долговечном локальном хранилище с хэшами.

Claude Code `/animate` и Codex `$animate` вызывают роли и CLI по общему протоколу. По директиве владельца тяжёлую работу выполняет Codex. Блокировка эпизода допускает одного записывающего оркестратора. Передача содержит версию, статус, утверждения и следующий шаг.

До длительной задачи сохраняем stdout/stderr, PID и идентификатор загрузки системы, входы и итоговый статус. Ключ повторного использования включает содержимое входов, зависимый код, модель, параметры, промпт и окружение; Git SHA недостаточен. Новый текст аннулирует речь и зависимый монтаж. Существующий файл без совпавшего манифеста не считается пригодным. Платные результаты и завершённые этапы восстанавливаем сразу; покадровое продолжение рендера откладываем.

## Расширения движка и библиотека

В v1 вводим стабильные токены, отчёт выравнивания речи, настоящие паузы, нулевой дрейф/толчки/зерно и общий расчёт камеры для объектов и рамок. `hold` различает остановку камеры, объекта и сцены. Все состояния вычисляются от времени; проверяем повторные кадры и обратную перемотку.

В звуке исправляем отмеченные R5 огибающую и зависимость от `narr`, делаем ducking от всех речевых огибающих, шины речи/среды/музыки/эффектов, панораму и сохранение хвостов. Отсутствующий обязательный звук завершает сборку ошибкой. Измеряем декодированный AAC обоих выходных файлов; цель студии −15 LUFS-I ±1, true peak ≤−1 dBTP. Это внутренний порог, не универсальное правило площадок.

Переходы: cut, затемнение, монтаж по действию, J/L. Двухсценовый dissolve/wipe добавляем по необходимости аниматика: независимые камеры, пространства SVG-ID, единственный слой титров. MP4 декодируем локально, нормализуем и читаем по индексу кадра, без сети в рендере.

Семь жанров: наука, документалистика, драма, микродрама, экшн, хоррор, комедия. Карточка: обещание, исходное знание, биты, хук/финал, ограничения, пример/антипример, приёмка. Длительности ориентировочные; стиль выбирается независимо.

Доводим два компактных набора: «Лаборатория» — сравнение, преобразование, контрпример, финал, спокойная камера и предметные акценты; «Камерная драма» — общий план, взгляд, реакция, выбор, локальный свет и тишина. Каждый содержит кириллицу, композиции, безопасные зоны, движение, звук и демонстрацию. Экшн получает сценарную пробу; полный пакет позже. Новые профили явно вводим в CLAUDE/FORMAT и оба навыка; `legacy` сохраняет прежнее поведение. До этой миграции действующие инструкции не отменены.

## Генеративный адаптер и решения владельца

Один медиамаршрут, кандидат — WaveSpeed. Интерфейс: `capabilities, validate, estimate, submit, poll, fetch, reconcile, cancel`; неподдерживаемые операции обозначаются явно. Задание содержит назначение, `model_id`, prompt, хэши референсов, длительность, начальное/конечное состояние, монтажные запасы, лимит денег/попыток и SVG-замену. Модель квалифицируем конкретным действием; фиксированной квоты генерации нет.

До `submit` атомарно резервируем верхнюю оценку стоимости. Журнал хранит fingerprint, попытку, job ID, quote/actual cost, результат и причину брака. Потеря ответа означает `submission_unknown`: сначала сверка, без повторного платного POST; резерв остаётся. Idempotency используем только при поддержке поставщика. Скачиваем результат до истечения URL, проверяем хэш и паспорт прав. Ключи вне Git и промптов. Числа и доказательные схемы рисует движок.

Владелец утверждает бриф/лимит, сценарий/кадры, аниматик с голосом/стилем, финальный файл. Решение: `gate, candidate_sha256, scope, decision, evidence`. «Делай целиком» делегирует промежуточные решения; повторно не спрашиваем. Смена тезиса или лимита требует согласования. Публикация — отдельное поручение.

| Разногласие | Выбор и основание |
|---|---|
| R1 объединяет редактора и режиссёра; A разделяет | Принимаю A: один ответственный шоураннер, отдельная постановочная функция позволяет оспорить красивый уход от темы |
| R3 требует шесть критиков; A/B/C — три | Три независимых прохода покрывают шесть функций; дополнительные роли назначаются по риску |
| R2: три поставщика и 10–20 секунд вставок | Отклоняю стартовую квоту: один медиамаршрут и выбранный TTS, допустим полностью SVG-выпуск |
| A предлагает четыре стиля, B/R4 три, C один и пробу | Два узких готовых пакета: проверяем объяснение и персонажную постановку без распыления на восемь оформлений |
| R3/R5 откладывают паузы; R5 восстановление — P2 | Обязательны в v1: без них теряются смысл и оплаченная работа; до M3 журнал и паузы ведём вручную |
| B/R5 предлагают двухсценовый композитор; C откладывает | Принимаю C для v1: сложность оправдывает конкретный утверждённый кадр |
| R3 выбирает веса, R5 обещает «исчезновение» результата | SPY объясняет ошибку исторического отбора. Обязательное исчезновение доходности не доказано; веса — следующий выпуск |
| A: шкала 0–4, C: 1–5 | Единая шкала 1–5, минимум 4 по каждой творческой оси; блокеры не усредняются |
