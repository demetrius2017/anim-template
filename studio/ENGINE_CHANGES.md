# W3 — движок, M3 / первая часть

18 октября 2026. Реализованы шесть пунктов поручения. Основание: ARCHITECTURE.md, ROADMAP.md, research/r5_engine_audit.md и consilium/B_architect.md. Сценарии пилота, роли и студийные схемы не изменялись. Коммитов, push и платных генераций нет.

## 1. Ducking и речь без рассказчика

`mixlib.env_follow()` учитывает реальный шаг обновления 32 отсчёта: атака .03 с и отпускание .35 с больше не растягиваются в 32 раза. `Mix.duck()` использует максимум отдельных огибающих **всех текущих обработанных** речевых дорожек: противофаза голосов не скрывает речь. Выпуск без `narr` нормирует остальные роли по активной речи; оставшийся от предыдущей версии `voice_narr.wav` не подмешивается.

Исправление намеренно меняет звук. Старые слуховые заключения не относятся к новому миксу. Численные тесты проверяют времена реакции, тишину, выпуск без narr и противофазные голоса.

## 2. Паузы, акценты, фокус и токены

Старые `text`, `pause`, `voice`, разметка `*` / `~` работают. `pause_after` — секунды тишины после фразы, алиас `pause`; одновременно задавать их нельзя. Внутри фразы можно использовать **вместо text** сегменты:

```json
{
  "id": "bias",
  "voice": "narr",
  "spans": [
    {"text": "Этот список пришёл"},
    {"text": "из будущего.", "emphasis": true, "focus": "future_list", "pause_after": 0.7},
    {"text": "Пересчитаем", "token_id": "bias.recalculate"}
  ],
  "pause_after": 0.2
}
```

Каждый сегмент синтезируется отдельно через edge-tts. `emphasis: true` задаёт более размеренный темп `+0%`; это конкретная реализация акцента, не обещание SSML-эмоции. Явные `rate` и `pitch` переопределяют темп/высоту; доступны на фразе и сегменте. `focus` — строковый смысловой идентификатор. Произносительный знак ударения U+0301 и цветовая разметка остаются отдельными средствами. Фактическую интонацию и швы сегментов нужно прослушивать; в этой работе сетевой TTS не запускался.

Паузы вставляются настоящими нулевыми PCM-отсчётами; все последующие слова и фразы сдвигаются. Время TTS — сетка 48 кГц с `*_sample`; `words.json` отдельно сохраняет исходные границы и диагностику alignment. Потерянное речевое слово блокирует TTS; неподтверждённое сопоставление ключевого токена (`focus`, `emphasis`, явный `token_id`) также блокируется. Неотмеченный legacy fallback остаётся явно записанным в диагностике.

Токен без явного имени получает `<phrase_id>.<индекс_с_нуля>`. Явный `token_id` допустим на односословном сегменте и должен быть уникален. В `story.py` доступны:

```python
E.token('bias.recalculate')       # начало слова; end=True — конец
E.focus('future_list')            # начало группы; end=True — конец
E.pause_end('bias')               # конец паузы после фразы
```

`E.t/te/wt/wfind` сохраняются. `story.json` экспортирует `token_map` и интервалы `pauses`, включая внутренние паузы сегментов. Титры делятся по паузам, остаются на экране до конца явной паузы, получают визуальный акцент и `data-focus`. Схлопывание словесных чисел в цифры сохраняет исходные токены и фокус; через внутреннюю паузу числа не склеиваются. Это расширение существующей шкалы, не весь будущий графовый компилятор студии.

## 3. Остановка камеры

```python
E.shot('bedroom', E.t('bias'), {}, {
    'z0': 1, 'z1': 1.08,
    'drift': 0, 'kicks': 0,
    'hold': [[E.focus('future_list'), E.token('bias.recalculate')]]
})
```

`drift=0` убирает дрейф, `kicks=0` — толчки. `hold` использует абсолютные полуоткрытые интервалы `[start,end)` внутри плана и фиксирует всю трансформацию камеры на её значении в начале интервала. Сцена и речь продолжаются. После hold камера возвращается к абсолютной траектории: при меняющемся зуме возможен скачок, его нужно учитывать в постановке. Для полностью статичного плана задайте также `z0=z1` и одинаковые x/y. Камера и привязанные рамки используют общий расчёт; рамки теперь учитывают толчок. Зерно и анимации объектов не замораживаются.

## 4. Контракты и защита `--skip-tts`

`engine_contracts.py` проверяет поля сценария, голоса, уникальность фраз/токенов, конечность времён, источники планов, существование сцен и локальных ресурсов. Планы обязаны покрывать шкалу подряд; пустоты, обратные и перекрывающиеся интервалы запрещены. Проверяются интервалы hold/fades/capOff и ссылки страниц титров. Разные наложения могут идти одновременно: видоискатель, рамка и подпись — законная композиция. Произвольные параметры конкретной legacy-сцены `p` пока остаются ответственностью самой сцены, полный студийный реестр параметров здесь не реализован.

После успешного TTS атомарно появляется `build/tts_manifest.json`: SHA-256 канонического сценария, настроек используемых голосов, `words.json` и WAV-дорожек. Изменение сценария **во время** синтеза блокирует запись квитанции. Изменённые текст/паузы/акценты/настройки/дорожки или отсутствующие файлы блокируют `--skip-tts` до раскадровки и микса. Неизвестная сцена также вызывает ошибку runtime вместо пустого кадра.

Единственный миграционный baseline — `legacy_tts_receipts.py`, фиксирующий точные исходные байты `example`, наблюдавшиеся 18 октября. Это позволяет выполнить обязательную сборку старого примера без нового TTS и без автоматического доверия произвольным старым файлам. Baseline — проверка неизменности, не свидетельство исторического синтеза или прослушивания. Для других выпусков без манифеста нужен новый TTS; автоматического принятия по совпадению текста титров нет.

## 5. Локальный MP4

```python
E.video('assets/insert.mp4', E.token('bias.recalculate'),
        in_=0.2, out=1.7, speed=1, fit='contain',
        cam={'z0': 1, 'z1': 1, 'drift': 0, 'kicks': 0})
# Следующий E.shot/E.video задаёт конец вставки; последний план заканчивается E.dur.
```

В JSON: `source={kind:'video', path, in, out, speed, fit}`. Путь локальный, относительно папки выпуска; `out` обязателен, `in=0`, `speed=1`, `fit=contain` по умолчанию. Поддерживаются contain/cover. Интервал источника обязан покрывать длительность плана, `out` проверяется по ffprobe.

`media_assets.py` заранее нормализует исходник в PNG 30 fps, сохраняя кеш `build/media_cache/`. Ключ содержит SHA-256 MP4, версию ffmpeg, фильтр и fps; отдельные PNG имеют свои хэши. Подготовка защищена межпроцессной блокировкой. Выбор кадра: `floor((in + (t - shot.t0) * speed) * 30)`. Браузер ждёт декодирования изображения перед снимком; сети и video-seek при рендере нет. Проверены повторные запросы в обратном порядке и повреждение кеша.

Звук MP4 автоматически не подмешивается. Импорт занимает уже заданный интервал; для немой вставки между репликами сначала задайте соответствующую паузу сценария. Автоматическое раздвигание готовой речи импортом и внешний генеративный API не входят в эту часть.

## 6. Отчёт после AAC

После кодирования обеих копий `build.py` декодирует звук каждой через ffmpeg loudnorm и пишет `build/build_report.json`. Для каждого MP4: SHA-256, LUFS-I, true peak dBTP, LRA и результат порогов −15 ±1 LUFS / ≤−1 dBTP. В отчёте также хэши входных script/words/story/mix. Измерение относится к самому AAC-файлу, а не WAV до лимитера.

Выход за пороги завершает полную сборку ненулевым кодом, сохраняя MP4 и отчёт для исправления. `listening_status` и `editorial_status` остаются `unknown`: измерение не заменяет прослушивание или проверку понимания. `--sheet`/`--no-render` AAC не создают и не выдают измерение старого MP4 за результат новой сборки.
